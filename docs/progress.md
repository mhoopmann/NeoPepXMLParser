## Not yet implemented

Agreed in discussion or raised as a suggestion, and not started. None blocks a release.

- **More fixtures.** The suite has one real file (Comet, PeptideProphet, iProphet). Files with
  PTMProphet, Libra, XPRESS label-free, Quantic, Kojak crosslinks, and an older schema version
  would each exercise writers that no test touches today. The owner supplies source copies in a
  local folder outside the repository; the recipe is in `tests/data/README.md`. Each new fixture
  needs its expected-output file generated by the writer and a row in that README's table.
- **A process for bumping the pinned expat.** The kits bundle libexpat at
  `NEOPEPXML_EXPAT_GIT_TAG` (`cmake/NeoPepXMLExpat.cmake`). Dependabot does not watch a
  FetchContent pin, so an expat security release means: bump the tag, push `dev`, check the dev
  kits, merge, and run the Release workflow. Nobody is reminded to do this today.
- **A namespace.** The library has none. Adding one is a source-breaking change for every
  consumer and belongs with a major version, not a patch.
- **Strict mode for unknown elements.** `read()` now skips unknown elements with a warning. An
  option to fail instead was suggested and not built; add it if a consumer needs it.
- **A `validate()` call.** The writers no longer enforce "required" attributes. If schema-level
  checking is wanted, it should be a separate call that returns findings, not part of `write()`.

## Declined or deferred, with the reason

- Per-hit search-hit filter semantics: declined. `setFilterSearchHit()` keeps queries whose
  top-ranked hit is the peptide, which is what the code did whenever it worked (BUG-3).
- PDB files in the Windows kits: deferred until someone asks; keeps the kits small.
- Windows ARM64 and Linux aarch64 kits: out of scope; those users build from source.
- Debug builds in the Linux and macOS kits: Release only, by decision. Windows ships both
  because MSVC cannot mix Debug and Release runtimes.
- ABI stability through pimpl: declined. The README states there is no ABI guarantee and the
  shared library's soversion equals the full version.

## How to

- **Regenerate the expected output** after an intentional change to the writer's format: build,
  run the tests (the round-trip test writes `build/<preset>/tests/roundtrip_pass1.pep.xml`), copy
  that file over `tests/data/expected/<fixture>.pep.xml`, review the diff, and commit it with
  the change that caused it.
- **Start a release cycle:** bump `project(VERSION ...)` in `CMakeLists.txt` and open a new
  section in `CHANGELOG.md` before the first push to `dev`, so dev kits carry the new number.
- **Cut a release:** merge `dev` into `main`, run the Release workflow from `main`, inspect the
  pre-release, promote it in the GitHub UI.

## Conventions worth knowing

- Class names mirror pepXML element names, inconsistencies included. They are not to be renamed.
- Fixtures under `tests/data/` are exempt from line-ending conversion and compared byte for byte.
- The library is silent by default; `setDiagnosticOutput(true)` and `setProgressOutput(true)`
  are the only console output.
